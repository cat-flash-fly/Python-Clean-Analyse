# 数据清洗与业务分析项目（Python）
## 项目简介
本项目基于山东省内城市订单原始数据集，使用 Python（Pandas）完成全流程数据清洗与业务分析。针对原始数据中存在的缺失值、日期格式混乱、文本字段空格污染、支付方式不规范、金额异常值、重复记录等真实数据质量问题，执行标准化清洗流程，输出可用于统计分析的干净数据集，并基于清洗后的数据开展城市、支付方式、时间、用户等多维度业务统计。
## 原始数据存在的质量问题
1. **缺失值问题**：`order_date`、`city`、`pay_amount`、`pay_type` 字段均存在空值，导致对应订单无法纳入时间、地域、金额维度统计
2. **日期格式混乱**：日期同时存在 `YYYY-MM-DD`（横杠）、`YYYY/MM/DD`（斜杠）、`YYYY.MM.DD`（点号）三种格式，且均为文本类型，无法直接做时间维度计算
3. **文本字段空格污染**：`city`、`pay_type` 字段大量存在前后空格、中间插入空格的情况，例如「 泰安 」「支付 宝」「微 信」，会导致分组统计时同一城市 / 支付方式被拆分为多组
4. **支付方式不规范**：同一种支付方式存在多种写法，例如支付宝对应「支付宝」「支付 宝」「zhifubao」「微 xin」等错写、别名、拼音，无法直接聚合统计
5. **金额异常值**：`pay_amount` 存在**负金额**（退款 / 错误数据）和**超大大额异常值**（如 9999.99、32000、28900 等远高于正常客单价的异常数据），会严重拉高销售额均值，造成统计失真
6. **重复记录问题**：文件末尾存在多条 `order_id` 重复的订单行，会导致订单量、销售额统计虚高
## 数据清洗流程
1. **数据读取与基线统计**：导入原始 CSV，输出清洗前总行数、各字段缺失值数量，作为数据质量基线
2. **缺失值处理**：针对 `order_date`、`city`、`pay_amount` 核心业务字段，`city`缺失值用"未知"填充，对`order_date`、`city`缺失值进行标记，保留有效订单
3. **日期格式标准化**：将日期文本统一转换为标准 datetime 格式，对于无法转换的异常日期进行标记，支持后续月度、季度时间维度分析
4. **文本字段去空格**：对 `city`、`pay_type` 字段执行去除前后空格、清理中间多余空格操作，保证同一维度值写法唯一
5. **支付方式归一化**：通过映射规则，将所有别名、错写、拼音统一归类为「支付宝」「微信」两类标准值
6. **异常金额清洗**：标记支付金额 ≤ 0 的无效订单；基于业务常识判定超大额异常值并剔除，避免极端值干扰统计结果
7. **重复数据去重**：按 `order_id` 唯一标识删除重复订单记录，保留唯一有效行
8. **清洗结果校验**：输出清洗后剩余数据行数、各字段完整性校验结果，核对数据剔除比例，验证清洗效果
## 数据分析结果
基于清洗后的干净订单数据集，开展数据分析得到:
### 该订单原始订单数为2035条，其中重复订单数35条，去除后总订单数2000条，总金额468989.21元。经过去重、异常值过滤、空值剔除，格式校准以后，有效订单数1929条，有效金额312630.16元，有效客单价约162.07元。
### 累计发现各类数据质量问题123条，异常金额156359.05元，占去重后总金额33.33%。各类异常分布:主键重复35条占比1.7%；字段缺失(城市/日期/金额)共55条，占比2.7%；日期格式非法7条，占比0.34%；支付方式不规范6条，占比0.29%；负值金额（退款/冲正）11条，金额合计-1575.88元；大额金额9条，金额合计153354.65元，占全部异常金额的 98.1%，是金额偏差的绝对主要来源。
### 支付方式:支付宝支付1003条，占比50.15%，微信支付997条，占比49.85%，用户支付偏好无明显倾斜，渠道均衡性较好；城市分布:订单前三城市为日照，淄博，威海，合计占比25.6%，订单地域分布较为分散，暂无单一核心城市。时间趋势：3月为订单高峰，单月订单354条，占总有效订单的 17.9%。
